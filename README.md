# Gоффер — "Итоги года" (Avito Hackathon, Кейс 3)

MVP веб-приложения для сценария **"Итоги года"**: тестовый профиль → генерация персональной истории → метрики, достижения, рекомендации, story → безопасный share.

Проект создан в рамках **Avito Hackathon** как самостоятельная параллельная реализация кейса 3.

> **Важно:** этот репозиторий является моей самостоятельной реализацией. В процессе разработки я параллельно участвовал в командной работе над основным проектом команды Gоффер. Для этой реализации использовалась общая исходная техническая база и первоначальные frontend/архитектурные решения команды, после чего я самостоятельно развивал проект в отдельном направлении и реализовал дополнительные продуктовые и технические решения.

### Почему я сделал отдельную реализацию

Мне было интересно проверить, насколько по-другому можно построить пользовательский сценарий «Итоги года», сохранив при этом понятную архитектуру и возможность воспроизводимого демо.

Вместо простой страницы со статистикой я стремился сделать полноценный пользовательский сценарий:

**профиль → персональные итоги → история → достижения → рекомендации → действие → share**

При этом я отдельно проработал несколько вариантов пользовательского поведения и сделал систему достаточно гибкой, чтобы recap формировался на основе характеристик конкретного профиля.

## Что представляет собой решение

Это не просто таблица статистики пользователя.

Приложение превращает данные о действиях пользователя в персональную историю:

* основные метрики;
* категории и интересы;
* достижения;
* persona;
* story;
* персональные рекомендации;
* CTA;
* возможность поделиться результатом.

Основная идея:

> **Не показывать пользователю набор логов, а рассказать ему историю его года на Авито и предложить следующий полезный шаг.**

## Архитектурный подход

Backend построен с разделением ответственности между слоями приложения.

Основные части:

* HTTP/API layer;
* use cases;
* domain/business logic;
* repositories;
* PostgreSQL;
* Redis cache.

Frontend разделён на страницы, компоненты, hooks и API-слой.

Отдельное внимание уделено тому, чтобы логика генерации recap была отделена от HTTP handlers и могла тестироваться независимо.

---

## Почему PostgreSQL

Реляционная модель (`users`, `actions`, `recaps`) используется для основных сущностей, а **JSONB** — для гибких данных recap:

* `achievements`;
* `recommendations`;
* `story`;
* `top_categories`.

Миграции и seed позволяют получать **воспроизводимые тестовые профили**.

Redis используется как кэш recap и не является источником истины.

Тестовые данные используются для демонстрации MVP, но слой репозиториев и разделение бизнес-логики позволяют в дальнейшем заменить seed-события реальными событиями продукта.

# Сценарий для жюри (5–7 минут)

Рекомендуемый сценарий демонстрации:

### 1. Главная

Показать **5 тестовых профилей** с persona-badge.

### 2. Генерация итогов

Выбрать профиль → **«Итоги 2025»** → generate.

Показать:

* story;
* основные цифры;
* достижения;
* рекомендации;
* CTA.

### 3. Разные типы пользователей

Показать профиль **Елена Новичок**:

* «тихий год»;
* отсутствие достижений;
* персональные рекомендации.

Это демонстрирует, что recap зависит от поведения пользователя, а не является одинаковым для всех.

### 4. Share

Открыть share-карточку:

* данные представлены в обезличенном виде;
* в теле share-ответа нет `id` / `user_id`;
* результат можно скачать как PNG.

### 5. Сравнение

Выбрать два профиля → **«Сравнить»**.

Показать различия между профилями и их персональными результатами.

### 6. Перегенерация

Использовать **«Перегенерировать все»** для повторного пересчёта recap перед демонстрацией.

### 7. Авторизация

Войти:

```text
demo / demo123
```

После входа доступны:

* **«+ Добавить профиль»**;
* создание профиля;
* выбор типа поведения;
* опциональный URL фотографии;
* абстрактный аватар при отсутствии фотографии;
* удаление созданного профиля.

Seed-профили через UI не удаляются.

### 8. Новый пользователь

Создать новый профиль и сгенерировать для него собственные итоги.

# API

| Метод    | Путь                                | Auth   | Описание                          |
| -------- | ----------------------------------- | ------ | --------------------------------- |
| `GET`    | `/health`                           | —      | Healthcheck                       |
| `GET`    | `/api/profiles`                     | опц.   | Список профилей                   |
| `GET`    | `/api/profiles/{id}`                | опц.   | Профиль                           |
| `POST`   | `/api/profiles`                     | **да** | Создать профиль + демо-активность |
| `DELETE` | `/api/profiles/{id}`                | **да** | Удалить профиль                   |
| `POST`   | `/api/recap/generate`               | опц.   | `{"user_id","year"}` → recap      |
| `GET`    | `/api/recap/{user_id}/{year}`       | опц.   | Личный recap                      |
| `GET`    | `/api/recap/{user_id}/{year}/share` | опц.   | Share без идентификаторов         |
| `POST`   | `/api/recap/generate-all?year=2025` | опц.   | Пересчёт всех recap               |
| `POST`   | `/api/auth/login`                   | —      | Сессия (cookie)                   |
| `POST`   | `/api/auth/register`                | —      | Регистрация                       |
| `POST`   | `/api/auth/logout`                  | —      | Выход                             |
| `GET`    | `/api/auth/me`                      | cookie | Текущий аккаунт                   |

Генерация recap:

```bash
curl -s -X POST http://localhost:8000/api/recap/generate \
  -H 'Content-Type: application/json' \
  -d '{"user_id":"22222222-2222-2222-2222-222222222222","year":2025}'
```

В ответе:

* `total_*`;
* `top_categories`;
* `achievements`;
* `recommendations`;
* `story`.

В share-ответе пользовательские идентификаторы не передаются.

# Ограничения MVP

* Используются тестовые профили и seed-данные, а не реальные production-события Avito.
* Share URL может содержать `user_id`, при этом **тело share-ответа обезличено**.
* Рекомендации представлены как продуктовые CTA и не являются deep-link на конкретные объявления.
* Удаление seed-профилей через UI отключено.
* Проект является хакатонным MVP и не является production-интеграцией с инфраструктурой Avito.
