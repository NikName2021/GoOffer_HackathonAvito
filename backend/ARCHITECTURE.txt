================================================================================
                         ПОТОК ДАННЫХ (REQUEST FLOW)
================================================================================

  HTTP Request
        ↓
  Middleware: CORS → Logger → Recovery → OptionalAuth
        ↓
  ServeMux → Handler (path values, JSON body, валидация)
        ↓
  Use Case
        ├── ports → Postgres (users / actions / recaps / accounts)
        ├── ports → Redis cache (или noop)
        ├── calculateMetrics
        ├── AssignAchievements
        ├── BuildStory
        └── BuildRecommendations
        ↓
  DTO (Domain → JSON)
        ↓
  HTTP Response

Генерация recap (POST /api/recap/generate):
  1. Проверка user
  2. Cache hit? → вернуть
  3. Actions за год из Postgres
  4. Metrics → Achievements → Story → Recommendations
  5. Save recap (ON CONFLICT user_id+year) + cache 24h
  6. 201 + RecapResponse

Создание профиля (POST /api/profiles) — только с сессией:
  1. RequireAuth / AccountFromContext
  2. Validate name, profile_type (seller|buyer|veteran|newbie|universal)
  3. Avatar: URL из запроса ИЛИ defaultAvatar (abstract, не фото людей)
  4. UserRepository.Create
  5. ActionRepository.SeedDemoActivity(userID, profile_type, year)
  6. 201 + ProfileResponse

Удаление профиля (DELETE /api/profiles/{id}) — только с сессией:
  1. RequireAuth
  2. UserRepository.Delete → CASCADE actions/recaps
  3. 204 No Content


================================================================================
                              API ЭНДПОИНТЫ
================================================================================

  GET    /health
  GET    /api/profiles
  GET    /api/profiles/{id}
  POST   /api/profiles                         # auth required
         Body: { "name", "profile_type", "avatar?", "year?" }
  DELETE /api/profiles/{id}                    # auth required

  POST   /api/recap/generate
         Body: { "user_id": "<uuid>", "year": 2025 }
  GET    /api/recap/{user_id}/{year}
  GET    /api/recap/{user_id}/{year}/share     # без id / user_id в JSON
  POST   /api/recap/generate-all?year=2025

  POST   /api/auth/register
  POST   /api/auth/login                       # HttpOnly cookie gooffer_session
  POST   /api/auth/logout
  GET    /api/auth/me

  AUTH_REQUIRED=false (по умолчанию) — чтение профилей и recap без логина (демо кейса).
  AUTH_REQUIRED=true  — RequireAuth на /api/profiles (GET) и /api/recap/*.
  POST/DELETE /api/profiles всегда требуют сессию (если AuthService подключён).

================================================================================
                         ПРАВИЛА ГЕНЕРАЦИИ (КРАТКО)
================================================================================

  Действия: view | message | favorite | purchase | sale

  Ачивки (Slug → условие), пример:
    curious          ≥ 500 views
    explorer         ≥ 1000 views
    social_butterfly ≥ 50 messages
    seller_master    ≥ 5 sales
    shopaholic       ≥ 10 purchases
    enthusiast       ≥ 100 activity days
    veteran          ≥ 300 activity days

  Story persona: seller | buyer | mixed | explorer | newbie
  (UI также показывает veteran / universal с seed profile_type)

  Recommendations: до 3 CTA (категория, избранное, объявление, чаты, explore)
  Share-card: агрегаты + achievements + story + recommendations, без id/user_id.

  SeedDemoActivity при Create: шаблон счётчиков по profile_type → synthetic actions за year.

================================================================================
                         ТЕХНОЛОГИЧЕСКИЙ СТЕК
================================================================================

  Язык:          Go (см. go.mod; в Docker — golang alpine из Dockerfile)
  HTTP:          net/http (ServeMux, Go 1.22+ patterns) — без Gin
  БД:            PostgreSQL 17 (Compose)
  Кэш:           Redis (опционально, noop fallback)
  Драйвер БД:    jackc/pgx/v5
  Redis client:  redis/go-redis/v9
  UUID:          google/uuid
  Логирование:   log/slog (JSON)
  Крипто/auth:   golang.org/x/crypto
  Тесты:         testing + testify
  Линтер:        golangci-lint (.golangci.yml)
  Деплой:        Docker Compose (корень репозитория)

  Почему PostgreSQL: реляционная модель users/actions/recaps, JSONB для
  гибких полей recap, простой seed и миграции. Redis — только кэш.
