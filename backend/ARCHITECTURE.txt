================================================================================
                         ПОТОК ДАННЫХ (REQUEST FLOW)
================================================================================

  HTTP Request
        ↓
  Middleware: CORS → Logger → Recovery → OptionalAuth
        ↓
  ServeMux → Handler (path values, JSON body, валидация)
        ↓
  Use Case
        ├── ports → Postgres (users / actions / recaps / accounts)
        ├── ports → Redis cache (или noop)
        ├── calculateMetrics
        ├── AssignAchievements
        ├── BuildStory
        └── BuildRecommendations
        ↓
  DTO (Domain → JSON)
        ↓
  HTTP Response

Генерация recap (POST /api/recap/generate):

  1. Проверка user
  2. Cache hit? → вернуть
  3. Actions за год из Postgres
  4. Metrics → Achievements → Story → Recommendations
  5. Save recap (ON CONFLICT user_id+year) + cache 24h
  6. 201 + RecapResponse

================================================================================
                              API ЭНДПОИНТЫ
================================================================================

  GET  /health
  GET  /api/profiles
  GET  /api/profiles/{id}
  POST /api/recap/generate
       Body: { "user_id": "<uuid>", "year": 2025 }
  GET  /api/recap/{user_id}/{year}
  GET  /api/recap/{user_id}/{year}/share     # без id / user_id в JSON

  POST /api/auth/register
  POST /api/auth/login                       # HttpOnly cookie gooffer_session
  POST /api/auth/logout
  GET  /api/auth/me

  AUTH_REQUIRED=false (по умолчанию) — профили и recap без логина (демо кейса).
  AUTH_REQUIRED=true  — RequireAuth на /api/profiles и /api/recap/*.

  Действия: view | message | favorite | purchase | sale

    curious            ≥ 500 views
    explorer           ≥ 1000 views
    social_butterfly   ≥ 50 messages
    seller_master      ≥ 5 sales
    shopaholic         ≥ 10 purchases
    enthusiast         ≥ 100 activity days

  Story persona: seller | buyer | mixed | explorer | newbie
  Recommendations: до 3 CTA (категория, избранное, объявление, чаты, explore)

  Share-card: агрегаты + achievements + story + recommendations, без id/user_id.

================================================================================
                         ТЕХНОЛОГИЧЕСКИЙ СТЕК
================================================================================

  Язык:          Go (см. go.mod; в Docker — golang:1.25-alpine)
  HTTP:          net/http (ServeMux, Go 1.22+ patterns) — без Gin
  БД:            PostgreSQL 17 (Compose)
  Кэш:           Redis 7+ (опционально, noop fallback)
  Драйвер БД:    jackc/pgx/v5
  Redis client:  redis/go-redis/v9
  UUID:          google/uuid
  Логирование:   log/slog (JSON)
  Крипто/auth:   golang.org/x/crypto
  Тесты:         testing + testify
  Линтер:        golangci-lint (.golangci.yml)
  Деплой:        Docker Compose (корень репозитория)

  Почему PostgreSQL: реляционная модель users/actions/recaps, JSONB для
  гибких полей recap, простой seed и миграции. Redis — только кэш.
