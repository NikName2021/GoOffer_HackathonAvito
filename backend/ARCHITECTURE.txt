================================================================================
                          ПОТОК ДАННЫХ (REQUEST FLOW)
================================================================================

  HTTP Request (net/http ServeMux, Go 1.22+ patterns)
        ↓
  Middleware chain:
    Request-ID → Logger → Recovery → CORS → (Auth для /api/*)
        ↓
  Router → Handler (парсинг path/query/body, валидация)
        ↓
  Use Case (бизнес-логика)
        │
        ├──→ Repository (postgres) / CachedRecapRepository (redis + postgres)
        │         ↓
        │    Domain entities
        │
        ├──→ Generator: metrics → achievements → cards/charts
        │
        ├──→ Auth (sessions, password hash)
        │
        └──→ Mission (select / progress)
        │
        ↓
  DTO (Domain → Response) + единый response helper
        ↓
  HTTP Response (JSON) + Prometheus metrics / business events

================================================================================
                               API ЭНДПОИНТЫ
================================================================================

  System
    GET  /health
    GET  /metrics                          # Prometheus

  Auth
    POST /api/auth/register                # Body: credentials → Set-Cookie session
    POST /api/auth/login
    POST /api/auth/logout
    GET  /api/auth/me

  Profiles (требуют auth)
    GET    /api/profiles                   # Список профилей аккаунта
    POST   /api/profiles                   # Создание
    GET    /api/profiles/{id}
    PUT    /api/profiles/{id}
    DELETE /api/profiles/{id}

  Recap (требуют auth)
    POST /api/recap/generate               # Body: { "user_id": "uuid", "year": 2025 }
    GET  /api/recap/{user_id}/{year}
    GET  /api/recap/{user_id}/{year}/share # Share-card (без чувствительных данных)
    POST /api/recap/events                 # Трекинг бизнес-событий (opened, cta, …)

  Mission
    GET  /api/recap/{user_id}/{year}/mission
    PUT  /api/recap/{user_id}/{year}/mission  # Выбор миссии

================================================================================
                         ЗАВИСИМОСТИ МЕЖДУ СЛОЯМИ
================================================================================

  Внешний мир (HTTP)
        ↓
  Handlers + Middleware  ←── DTO
        ↓
  Use Cases              ←── ports (interfaces)
        ↓
  Domain                 ←── Repository implementations (postgres / redis)

  ⚠️ ПРАВИЛО: Зависимости направлены ВНУТРЬ.
     Внешние слои зависят от внутренних, но не наоборот.
     Use cases зависят только от ports, не от postgres/redis напрямую.

================================================================================
                              ТЕХНОЛОГИЧЕСКИЙ СТЕК
================================================================================

  Язык:          Go 1.22+
  HTTP:          net/http (stdlib ServeMux, Go 1.22 routing patterns)
  БД:            PostgreSQL 17+
  Кэш:           Redis 8+
  Драйвер БД:    pgx/v5 (github.com/jackc/pgx/v5)
  Redis client:  go-redis/v9
  Метрики:       prometheus/client_golang
  Крипто:        golang.org/x/crypto (пароли)
  Логирование:   log/slog (стандартный пакет)
  Конфигурация:  env (без обязательного godotenv в runtime)
  UUID:          google/uuid
  Миграции:      embed FS + собственный Apply() при старте
  Swagger:       OpenAPI 3 (docs/swagger.yaml)
  Линтер:        golangci-lint
  Docker:        Docker Compose (postgres + redis + backend)

================================================================================
                              КОМАНДЫ ЗАПУСКА
================================================================================

  Локальный запуск:
    cd backend
    go mod download
    go run ./cmd/server

  Через Docker (из корня репозитория):
    docker compose up -d          # инфраструктура + сервисы
    docker compose up             # с логами
    docker compose down

  Тесты:
    go test ./tests/unit/...
    go test ./tests/integration/...
    go test ./... -cover

  Линтер:
    make lint
    # или: golangci-lint run ./...

  Миграции:
    Применяются автоматически при старте приложения (migrations.Apply).
    SQL-файлы лежат в migrations/*.up.sql и встраиваются через go:embed.
