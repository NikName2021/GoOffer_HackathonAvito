GOOFFER BACKEND — CURRENT ARCHITECTURE
======================================

Transport
  net/http ServeMux -> request-id/logger/recovery/CORS -> auth middleware
  -> handlers -> explicit request/response DTO.

Use cases
  auth       account registration, Argon2id passwords, hashed sessions
  profile    owner-scoped CRUD over item-level viewed_ads/own_ads
  generator  UTC-year metrics -> summary/cards/achievements -> recap save
  mission    owner-scoped selection and progress from events after selection

Persistence
  PostgreSQL is the source of truth for accounts, sessions, profiles, recaps
  and missions. Embedded SQL migrations run transactionally on startup.
  Redis is a fail-open read-through cache for generated recaps only.

Recap source of truth
  User.Views (viewed_ads JSONB) and User.OwnAds (own_ads JSONB). The obsolete
  actions/categories model is removed by migration 008 and has no repository
  or generator dependency.

Share boundary
  Full Recap -> ShareRecapResponse -> ShareRecapCardDTO allowlist. The share
  endpoint is authenticated and owner-only; public token links are not in MVP.

Dependency direction
  delivery -> usecase ports/usecases -> domain
  repository implementations -> usecase ports/domain
  cmd/server wires concrete implementations.

See backend/README.md for setup, contracts, generation rules, privacy, CI and
known limitations. See backend/docs/swagger.yaml for the HTTP specification.
