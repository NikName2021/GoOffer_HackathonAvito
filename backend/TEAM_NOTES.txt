GOOFFER BACKEND — АКТУАЛЬНЫЕ ЗАМЕТКИ КОМАНДЫ
================================================

Назначение файла
  Краткая карта текущего backend для совместной разработки. Это не backlog и
  не API-контракт. Подробные правила находятся в backend/README.md, публичный
  HTTP-контракт — в backend/docs/swagger.yaml, архитектурные границы — в
  backend/ARCHITECTURE.txt.

Текущее состояние
  Backend реализован на Go 1.22 и стандартном net/http. PostgreSQL является
  постоянным источником истины, Redis — необязательным кэшем готовых recap.
  Все прикладные /api-маршруты требуют cookie-сессию; административные маршруты
  дополнительно требуют account.is_admin=true.

Основные модули
  internal/domain/
    Account, User, Recap, Achievement, Mission и CardDefinition.

  internal/usecase/
    auth            регистрация, вход, выход и сессии;
    profile         CRUD профилей с проверкой владельца;
    generator       годовые метрики, summary, cards, charts и achievements;
    mission         выбор миссии и расчёт прогресса;
    carddefinition  административные правила дополнительных карточек;
    ports           интерфейсы внешних хранилищ.

  internal/repository/
    postgres        аккаунты, сессии, профили, recap, missions и card definitions;
    redis           cache-aside для recap с TTL 24 часа.

  internal/delivery/
    handlers        auth, profiles, recap, missions и admin card definitions;
    middleware      request ID, logger, recovery, CORS, auth и admin guard;
    dto             отдельные модели запросов, обычных ответов и share allowlist.

  internal/observability/ и internal/server/
    Prometheus-метрики, бизнес-события, маршрутизация и HTTP lifecycle.

Источник данных recap
  Единственный источник пользовательской активности — User.Views (viewed_ads)
  и User.OwnAds (own_ads) в JSONB профиля. Просмотры, лайки и покупки являются
  item-level событиями с UTC-временем. Устаревшие actions/categories удалены
  миграцией 008 и не используются генератором.

Миграции
  001_init                         базовые users/categories/actions/recaps;
  002_seed_test_profiles           исходные демонстрационные профили;
  003_profile_details              расширенные поля профиля;
  004_auth                         accounts, sessions и владелец профиля;
  005_profile_crud                 own_ads/viewed_ads для CRUD;
  006_recap_cards                  backend-driven карточки recap;
  007_recap_missions               миссии следующего года;
  008_remove_legacy_actions        удаление старого источника actions/categories;
  009_admin_card_definitions       администратор и правила дополнительных карточек;
  010_enrich_seed_profiles         шесть связанных реалистичных персон;
  011_add_seed_activity_and_images 50+ событий на профиль и фото объявлений.

  *.up.sql встраиваются через go:embed и применяются транзакционно в
  лексикографическом порядке. Версии записываются в schema_migrations, а
  advisory lock защищает от параллельного применения. Уже опубликованную
  миграцию не переписываем: любое изменение схемы или данных получает новый
  последовательный номер и обратный *.down.sql.

Важные инварианты
  - профиль и recap доступны только владельцу;
  - чужой или отсутствующий ресурс возвращается как 404 без раскрытия наличия;
  - PostgreSQL записывается раньше Redis, ошибка кэша не ломает основной API;
  - share строится из сохранённого recap через allowlist и не содержит id,
    user_id, ad_id, image_url, reason, visualization, CTA или params;
  - годовые показатели считаются только из датированных событий выбранного
    UTC-года; недатированные likes/chats остаются только в profile API;
  - overview всегда является первой встроенной карточкой, next_step — финалом;
  - полный recap содержит не более девяти карточек.

Локальный запуск
  Из корня:
    cp .env.example .env
    docker network create result_year
    docker compose --env-file .env up -d --build --wait

  Backend через go run:
    docker compose --env-file .env up -d postgres redis
    cd backend
    DB_HOST=localhost DB_PORT=5446 \
    DB_USER=result_year DB_PASSWORD=result_year_dev_password DB_NAME=result_year \
    REDIS_URL=redis://localhost:6379 go run ./cmd/server

Проверки перед merge
  cd backend
  go test -mod=readonly ./...
  make lint
  make coverage

  Реальная интеграция:
    DB_HOST=localhost DB_PORT=5446 \
    DB_USER=result_year DB_PASSWORD=result_year_dev_password DB_NAME=result_year \
    REDIS_URL=redis://localhost:6379 make test-integration

Правила совместной работы
  - изменения HTTP-запросов и ответов синхронизируем со Swagger и DTO;
  - не добавляем бизнес-логику в handlers или PostgreSQL-адаптеры;
  - новые зависимости usecase выражаем портом, конкретную реализацию связываем
    только в cmd/server;
  - не используем Redis как источник истины;
  - seed предназначен для демо и должен быть отделён перед строгим production;
  - перед передачей изменений запускаем gofmt, tests, lint и diff check.
