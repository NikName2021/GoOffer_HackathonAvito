================================================================================
[ГОТОВО] ДОМЕН И БИЗНЕС-ЛОГИКА
================================================================================
Зона: Clean Architecture, generator, ачивки, story, рекомендации, unit-тесты.

domain/
  - User, Action, Category, Achievement, Recap
  - Recommendation { Code, Title, Description, ActionLabel, Category }
  - Story { Persona, Headline, Summary, Insights }
  - DefaultAchievements — 7 ачивок с фиксированными порогами
  - Account / Session (опциональный auth)

usecase/ports/
  - UserRepository, ActionRepository, RecapRepository, Cache
  - AccountRepository (+ session через postgres.SessionRepository)

usecase/generator/
  - generator.go         Execute / Get
                         actions → metrics → achievements →
                         story → recommendations → save + cache
  - metrics.go           views, messages, favorites, purchases, sales,
                         top-3 categories, activity_days
  - achievements.go      AssignAchievements
  - story.go             BuildStory (persona + тексты без PII)
  - recommendations.go   BuildRecommendations (1–3 CTA)

usecase/profile/
  - ListProfiles / GetByID

usecase/auth/
  - register / login / logout / authenticate
  - включается жёстко через AUTH_REQUIRED=true (middleware RequireAuth)

delivery/dto/
  - ProfileResponse
  - RecapResponse          — полный (с id, user_id)
  - ShareRecapResponse     — БЕЗ id и user_id
  - AchievementDTO, RecommendationDTO, CategoryStatDTO, StoryDTO

tests/unit/
  - generator_test.go
  - achievements_test.go
  - recommendations_test.go
  - story_test.go
  - auth_test.go

Запуск:
  cd backend && go test ./tests/unit/... -count=1 -v


================================================================================
ПРАВИЛА АЧИВОК (зафиксированы в domain + AssignAchievements)
================================================================================
  curious            >= 500 views
  explorer           >= 1000 views
  social_butterfly   >= 50 messages
  seller_master      >= 5 sales
  shopaholic         >= 10 purchases
  enthusiast         >= 100 activity days
  veteran            >= 300 activity days


================================================================================
ПРАВИЛА STORY
================================================================================
  Persona:
    sales>=5 && purchases>=5          → mixed
    sales>=3 && sales>=purchases      → seller
    purchases>=3 && purchases>sales   → buyer
    views>=500 || activity_days>=100  → explorer
    иначе                             → newbie

  Headline / Summary / Insights — детерминированные шаблоны по persona
  и метрикам. Без переписок, чужих ID и точных персональных данных.


================================================================================
ПРАВИЛА РЕКОМЕНДАЦИЙ (следующий шаг в продукт)
================================================================================
  1. Есть топ-категория + views     → «Продолжите в „{category}“»
  2. Много favorites, мало покупок  → «Вернитесь к избранному»
  3. Были sales                     → «Разместите новое объявление»
     иначе много views без сделок   → «Попробуйте продать ненужное»
  4. Messages без purchases         → «Продолжите диалоги»
  5. Fallback                       → «Исследуйте новые категории»
  Максимум 3 карточки. Sensitive data не включаем.


================================================================================
[ГОТОВО] ДАННЫЕ, API, ИНФРА
================================================================================
migrations/
  001_init                 — users, categories, actions, recaps
  002_seed_test_profiles   — 5 профилей + детерминированный seed actions
  003_auth                 — accounts / sessions
  004_recap_story          — column story JSONB
  migrate.go               — apply из main при старте

repository/
  postgres/  user, action, recap, account, session
  redis/     recap_cache, noop_cache (fallback без Redis)

API (AUTH_REQUIRED=false — путь демо):

  GET  /health
  GET  /api/profiles
  GET  /api/profiles/{id}
  POST /api/recap/generate     body: { "user_id": "<uuid>", "year": 2025 }
  GET  /api/recap/{user_id}/{year}
  GET  /api/recap/{user_id}/{year}/share   ← без id / user_id в JSON

Опционально:
  POST /api/auth/register | login | logout
  GET  /api/auth/me

  Demo: login=demo  password=demo123

HTTP-стек: net/http ServeMux (не Gin).
Middleware: CORS → Logger → Recovery → OptionalAuth; при AUTH_REQUIRED —
RequireAuth на profiles/recap.
